# 2.0.2 — Optional models for Hybrid v2 / 混合 v2 可选模型

## English

Version 2.0.2 adds two independently selectable observation helpers to the 2.0.1 baseline. Both **ViTTrack** and **NeuFlow v2** are off by default. Hybrid v2 and Full/Half Travel share the helpers; direct Pose, its optional L0 blend and Hybrid 1 do not silently inherit them. This record separates development checks from final source and package verification.

### Implementation

- `v2_models.py`: lazy wrappers for the official ViTTrack ONNX implementation and a pinned NeuFlow v2 ONNX export. Models are local data, not downloaded Python or pickle code. ViTTrack initializes from an independently accepted subject ROI. NeuFlow requires explicit NVIDIA CUDA; its DirectML graph failed actual loading, and slow CPU inference is not used as its realtime fallback.
- `v2_model_assist.py`, `camera_motion.py` and `regional_flow.py`: ordinary sparse/DIS measurements are attempted first. Neural flow is requested adaptively for insufficient tracking/region support, computed at most once per distinct frame pair, checked forward/backward and against image appearance, and sampled with bounded spatial support. ViTTrack only proposes a region membership mask for real tracked points. It does not replace the subject origin with a box center or confirm camera motion. Cuts, reference expiry and subject changes discard old tracker identity.
- `visual_pipeline.py` and `motion_reference.py`: route model settings only to v2-based analysis and present bilingual status/timing diagnostics. Diagnostic candidates or failed models are not observations. The two-second continuation rule, final gains/limits/speed handling and simulator's final-command contract remain intact.
- `v2_model_assets.py`: pinned URL/revision/size/hash registry, private model cache, explicit bounded downloads, cancellation, staging-file verification and atomic completion. Existing supported files are reused. `tools/export_neuflow_v2.py` records the reproducible conversion; upstream credits and licenses are in `THIRD_PARTY_NOTICES.md`.
- `app.py`, `config.py` and `integrated_preview.py`: independent default-off switches, synchronized sidebar/preview/start-dialog controls, explicit model selection/download, shared GPU setup and consistent save/load/reset behavior. New worker inputs are ordinary value snapshots. Active relevant changes stop analysis; changing the file of a disabled model does not interrupt it. Non-dropping download events and request tokens prevent stale completion from overriding reset/cancel or a later selection. Rejected choices and failed downloads preserve the previous model selection.
- Analysis Preview's **+ Models** group starts collapsed and uses the existing `ControlSidebar` scrolling/focus support when opened. Its height is limited to 140 DIP or 22% of the preview, whichever is smaller; it occupies its own single-column row so the legacy controls' minimum widths cannot push the scrolling viewport outside a narrow preview. Fonts are not reduced.

The ViTTrack artifact is **714,726 bytes**, SHA-256 `2990f0b7cd44d92afa48cd97db6de7be113fc1d9594fddb74e2725c10478e91d`. The separate NeuFlow ONNX artifact is **58,416,346 bytes**, SHA-256 `589127d720dfb8fb27d1733381dda4aa73bc23ccda3e0fe008f0d1bf691eac8f`. These are model file sizes, not memory requirements. Neither file is included in source or Windows ZIPs.

### Limits

Optional models are not a general accuracy guarantee. A tracked box can drift, and neural flow can reject or misestimate blur, deformation, occlusion and ambiguous image motion. The ordinary motion validators remain necessary. A neural flow pair costs additional time, and model loading can add an initial delay; isolated inference measurements do not establish end-to-end capture/output latency. The CPU route remains available through ordinary analysis and ViTTrack; NeuFlow requires the supported CUDA runtime.

Foreground/background separation, semantic contact, true depth and unseen targets remain uncertain. Missing models must never extend the two-second output estimate. No new real-hardware compatibility, joint mapping, inverse kinematics, collision detection or feedback is established. Models, optional runtimes, personal settings, logs, caches and local private paths must remain outside public application archives.

### 实现

- `v2_models.py`：按需加载官方 ViTTrack ONNX 与固定 NeuFlow v2 ONNX 导出版；模型作为本地数据，不下载执行 Python／pickle 代码。ViTTrack 从独立确认的主体框初始化。NeuFlow 明确要求 NVIDIA CUDA，其 DirectML 图实际加载失败；实时路径不会悄悄退回耗时 CPU 神经光流。
- `v2_model_assist.py`、`camera_motion.py`、`regional_flow.py`：先用原稀疏／DIS 运动，跟踪或区域支持不足时再自适应请求神经光流。同一帧对最多算一次，经过正反向及图像外观检查，以数量受限的分布式点补充。ViTTrack 只限定真实匹配点所属区域，不把框中心换成主体原点，也不确认运镜。切镜、参考过期或换主体时清除旧跟踪身份。
- `visual_pipeline.py`、`motion_reference.py`：模型选项仅进入 v2 分析，显示中英文状态／耗时；候选框或模型失败诊断不冒充观测。两秒估算、最终倍率／限位／速度处理与模拟器最终指令约定保留。
- `v2_model_assets.py`：固定来源、修订、文件大小及哈希，私有目录缓存、明确下载、取消、临时文件验证和原子完成；复用已有受支持文件。`tools/export_neuflow_v2.py` 保留可复现导出过程，来源及许可见 `THIRD_PARTY_NOTICES.md`。
- `app.py`、`config.py`、`integrated_preview.py`：独立默认关闭开关，侧栏／预览／启动框同步，模型选择／下载、共享 GPU 设置、保存／读取／恢复默认一致。新工作线程输入为普通值快照；更改正在使用的选项会停分析，准备未启用模型的文件不会中断。可靠完成事件和请求标识防止旧下载覆盖重置、取消或后选文件；拒绝选择／下载失败保留原模型选择。
- 分析预览的 **+ 模型** 默认收起，展开后复用 `ControlSidebar` 的横纵滚动与焦点可达性。高度上限为 140 DIP 与预览高度 22% 中较小者，单独使用预览单列，避免旧控件最小列宽把滚动视口推出窄窗口；不缩小字号。

### 局限

模型不是所有场景的准确率保证。跟踪框可能漂移；神经光流在模糊、形变、遮挡和歧义画面中仍可能拒绝或误判，必须保留原运动验证。计算光流会增加耗时，首次加载也可能带来延迟；单次推理数据不能代表采集到输出的整体延迟。原分析与 ViTTrack 可用 CPU，NeuFlow 需要受支持的 CUDA 运行库。

主体／背景分离、语义接触、真实深度和画外目标仍不确定；模型缺失不能延长两秒输出估算。没有新增真实硬件兼容性、关节映射、逆运动学、碰撞检测或反馈保证。公开软件包不得含模型、可选运行库、个人设置、日志、缓存或本机隐私路径。
